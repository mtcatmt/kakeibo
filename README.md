# 家計簿（複式簿記・PWA）

iPhoneのホーム画面に追加して使う、複式簿記の家計簿。データはiPhoneの中（IndexedDB）にだけ保存され、サーバーには送られない。

## ファイル

| ファイル | 内容 |
|---|---|
| `index.html` / `style.css` | 画面の骨組みと見た目（ダークモードはiPhoneの設定に合わせて切り替わる） |
| `app.js` | 画面の動き（入力・履歴・カレンダー・グラフ・設定） |
| `ledger.js` | 帳簿の計算（残高・純資産・月別集計・固定費の自動作成） |
| `calendar.js` | カレンダーの計算（予定名の時間の読み取り・並び順・祝日・.ics の取り込み） |
| `charts.js` | グラフの描画（SVG） |
| `sw.js` | オフラインで開くためのService Worker |
| `manifest.webmanifest` / `icons/` | ホーム画面に追加したときの名前とアイコン |
| `tests/` | `ledger.js`・`calendar.js` のテスト（`node --test tests/*.test.mjs`） |
| `docs/calendar-requirements.md` | カレンダーの要件定義と、作りながら決まったこと |
| `CLAUDE.md` | 開発するときの決まり（版の上げ方・テスト・確認の仕方） |

## GitHub Pagesに置く手順

1. GitHubで新しいリポジトリを作る（例：`kakeibo`）。無料プランでPagesを使うには **Public** にする。公開されるのはプログラムだけで、家計のデータは含まれない。
2. リポジトリの画面で「Add file」→「Upload files」を選び、このフォルダの中身（`index.html` などのファイルと `icons` フォルダ）をドラッグして「Commit changes」。
3. 「Settings」→「Pages」で、Source を「Deploy from a branch」、Branch を `main` と `/ (root)` にして「Save」。
4. 1〜2分後に `https://<ユーザー名>.github.io/kakeibo/` で開けるようになる。

## iPhoneでの使い始め

1. 上のURLをChrome（またはSafari）で開き、共有メニューから「ホーム画面に追加」を選ぶ。
2. 以後はホーム画面のアイコンから開く。ブラウザのタブで開いた場合とはデータが別々になる。
3. 設定画面の「開始残高」で、使い始める日の現金・銀行口座・電子マネー・クレジットカード（未引き落としの利用額）・奨学金（返済あり）の残高を入れる。
4. 設定画面の「自動入力（固定費・積立・収入）」で、通信費・Claude・Amazon Primeの金額・日付・支払元を入れる。
5. 必要なら設定画面の「ロック（4桁の番号）」で番号を設定する。

URLの末尾に `?demo` を付けると、仮のデータで画面を確認できる（このとき入力した内容は保存されない）。

## アプリを更新したとき

`sw.js` の `CACHE` の番号を上げてからアップロードする（例：`kakeibo-v1` → `kakeibo-v2`）。番号を上げないと、iPhoneに保存された古いファイルが使われ続ける。新しい版が読み込まれると、画面下に「再読み込み」のボタンが出る。

## ロック（4桁の番号）

設定画面の「ロック（4桁の番号）」で番号を設定すると、次のときに番号の入力画面が出る。

- アプリを開いたとき
- ほかのアプリに切り替えてから、設定した時間（すぐ・1分・5分・15分。最初は1分）がたって戻ったとき

- 番号は、SHA-256 のハッシュ値（ランダムな値を加えたもの）にして IndexedDB の `lock` に保存する。帳簿のデータ（`state`）とは別のキーなので、バックアップのファイルには含まれず、「すべてのデータを削除」でも消えない。
- アプリの画面を開くのを止めるためのもので、端末に保存されたデータそのものは暗号化しない。
- 番号を忘れた場合は、ロック画面の「忘れた場合」から、データと番号をすべて削除して解除する。そのあと設定画面の「ファイルから復元」でバックアップを読み込む。Face ID を使っているなら、Face ID で開いて「番号を変更」でもよい。

### Face ID

番号を設定したあと、設定画面の「Face IDを使う」を押すと、番号の代わりに Face ID でも開けるようになる。番号は Face ID が使えないときのために残る。

- ロック画面が出ると、Face ID が自動で出る。出ないとき（iPhoneがタップなしの呼び出しを断ったときなど）は、テンキーの下の「Face IDで解除」を押す。
- 「番号を変更」「ロックをやめる」で今の番号を聞かれたときも、Face ID で通せる。
- 仕組みは WebAuthn（パスキー）。「Face IDを使う」で、iPhoneの「パスワード」アプリに「家計簿のロック」のパスキーができる（公開しているアドレス `mtcatmt.github.io` に結びつく）。パスキーの id を IndexedDB の `lock` の `bio` に保存する。
- サーバーがないので、Face ID が通ったかを端末の中で見るだけ。番号と同じく画面を開くのを止めるもので、データは暗号化しない。
- 「Face IDをやめる」「ロックをやめる」をしても、パスキーは「パスワード」アプリに残る。要らなければそこで削除する。公開するアドレスを変えたら、Face ID を設定し直す。

## 安全のために

- データは端末の IndexedDB にだけある。サーバーに送らず、外部のライブラリや解析タグも読み込まない。
- `index.html` の CSP（`Content-Security-Policy`）で、読み込むスクリプトをこのサイトのファイルだけに限っている。万一画面に HTML が入り込んでも、スクリプトは動かない。ファイルを外部から読み込むようにするときは、CSP も直す。
- 「ファイルから復元」では、科目・仕訳・固定費・予定の id・色・日付・金額の形を確かめ、合わないファイルは読み込まない（`ledger.js` の `validateState`、`calendar.js` の `validateCalendar`）。それでも、他人から受け取ったバックアップのファイルは復元しない。
- `main` に push できる人は、アプリを書き換えてデータを外へ送らせることができる。GitHub のアカウントには2段階認証を設定しておく。
- 書き出したバックアップのファイルには家計簿のすべてが入っている。置き場所に気をつける。

## 仕訳の作り方

| 入力 | 借方 | 貸方 |
|---|---|---|
| 支出 | 費用の科目 | 支払元（現金・カードなど） |
| 収入 | 入金先 | 収益の科目 |
| 振替 | 移動先 | 移動元 |
| 開始残高（資産） | 資産 | 開始残高 |
| 開始残高（負債） | 開始残高 | 負債 |

- カードの引き落とし：振替で、移動元＝銀行口座、移動先＝クレジットカード。
- 貸与奨学金の受け取り：振替で、移動元＝奨学金（返済あり）、移動先＝銀行口座。
- 月別の支出は、カードを使った日の月に数える（引き落とし日は振替なので支出に含まれない）。

## 立替（割り勘・ほかの人の分もまとめて払ったとき）

支出の画面で「＋ 立替を含める」を押し、支払った全額を入れてから、立替の金額を次のどちらかで決める。資産の科目「立替金」（名前に「立替」を含む資産の科目）がなければ、最初に保存したときに作られる。

- 割り勘：人数（自分を含む）を − ＋ で選ぶ。立替の金額は「支払額 ×（人数 − 1）÷ 人数」の1円未満を切り捨てた額で、端数は自分の分になる（例：1,000円を3人で割り勘 → 立替 666円、自分の分 334円）。
- 金額を指定：立替の金額を電卓で入れる（「全額」ボタンもある）。

人数と、割り勘か金額の指定かは、前回の入力が次の初期値になる。

| 出来事 | 入力 | 仕訳 |
|---|---|---|
| 3,000円をカードで払い、3人で割り勘 | 支出：食費 3,000円、割り勘 3人 | 借方 食費 1,000・立替金 2,000 ／ 貸方 クレジットカード 3,000 |
| 現金・電子マネー・銀行振込で返ってきた | 振替：立替金 → 受け取った現金・電子マネー・銀行口座 | 借方 現金など ／ 貸方 立替金 |
| 返ってこなかった | 支出：その他、支払元＝立替金 | 借方 その他 ／ 貸方 立替金 |

- 月別の支出には自分の分だけが入る。立替金の残高が、まだ返ってきていない金額になる。
- 全額が立替のときは費用の行がないので、履歴では振替として表示される。

## 金額欄の電卓

金額欄をタップすると電卓が開き（iPhoneのキーボードは出ない）、「決定」で計算結果を金額欄に入れる。

- + − × ÷ と小数点が使える。結果の1円未満は四捨五入する（例：980 × 1.1 → 1,078円）。
- 開いた直後に数字を押すと、それまでの金額を置き換える。演算の記号を押すと、それまでの金額に続けて計算する。
- パソコンでは、キーボードの数字・記号・Enter（決定）・Backspace・Esc（閉じる）も使える。

## 履歴の検索・絞り込み

- 検索欄：メモ・科目名・金額に含まれる文字で探す。空白で区切ると、すべての語を含む記録だけになる（例：「食費 昼」）。
- 「絞り込み」：科目（費用・収益）と、支払元・入金先（資産・負債）を選ぶ。
- 条件があるときは「すべての月」と「月ごと」を切り替えられ、該当する件数と、その記録の収入・支出の合計が出る。「条件を消す」で元の月別の一覧に戻る。

## 科目の色

費用の科目には色があり、入力画面の科目・履歴・グラフ・設定で使う。選べる色は16色と灰色。

- 科目を追加するときに色を選ぶ。最初は、まだほかの費用の科目に使われていない色が選ばれている。設定画面の「科目を追加」から追加した場合は、その色が自動で付く。
- あとから変えるときは、設定 →「勘定科目」の費用の科目の「色」を押す。
- 色を選んでいない科目（最初から入っている科目）は、並び順で8色を使い、9つ目以降と「その他」は灰色になる。

## 自動入力（固定費・積立・収入）

設定 →「自動入力」で、毎月・毎年決まった日の入出金を登録する。種類は入力画面と同じ3つ。

| 種類 | 借方 | 貸方 | 例 |
|---|---|---|---|
| 支出 | 費用の科目 | 支払元 | 通信費、Claude、Amazon Prime |
| 収入 | 入金先 | 収益の科目 | バイト①・②の給料、奨学金（返済なし） |
| 振替 | 移動先 | 移動元 | NISA積立（クレジットカード → NISA）、奨学金（返済あり）（奨学金（返済あり） → 銀行口座） |

金額がその月だけ違った場合は、履歴から自動で作られた仕訳を編集する。

## NISA（クレジットカードでの積立）

| 出来事 | 入力 | 仕訳 |
|---|---|---|
| 毎月の積立 | 設定 →「自動入力」の「NISA積立」に金額と日付を入れる | 借方 NISA（投資信託） / 貸方 クレジットカード |
| 評価額の更新（月1回程度） | 設定 または グラフ画面の「評価額を更新」 | 値上がり：借方 NISA / 貸方 評価差額、値下がり：借方 評価差額 / 貸方 NISA |
| 売却 | 先に評価額を売却額に更新し、振替：NISA → 入金先 | 借方 入金先 / 貸方 NISA |

- 積立は資産の購入なので、支出には数えない。
- 「評価差額」は純資産の科目で、残高はこれまでの値上がり額の累計。収益・費用ではないので、収入と支出のグラフには影響しない。純資産の推移には評価額で反映される。
- すでに持っている分は、「開始残高」で NISA（投資信託）に今の評価額を入れる。

## カレンダー

下のタブの「カレンダー」で、予定を月・週で見る。予定は家計簿のデータ（`state.calendar`）に入り、バックアップの書き出し・復元にそのまま含まれる。

- 月表示：週を縦に続けて並べ、上下にスクロールして見る（端に近づくと前後の月が足される）。月の間に空白は入れず、各月の1日は「12/1」のように月も出し、月の境目に階段状の線を引く。上の見出しに今見ている月が出て、「今日」で今月の1日を含む週に戻る。予定名はマスの中で中央ぞろえ（入りきらない予定名は始めから出す）。予定は種類の色の帯で、1日に4段まで出し（一日の予定と一日の一部の予定で見た目を分ける。下の「一日の予定と一日の一部の予定」）、5件以上ある日は3件と、入りきらない分を「+2」のように数で出す。日付をタップすると、その日の予定と、家計簿の支出の記録と合計が開く。
- 週表示：7日分を縦に並べる。各日の「＋」で予定を追加する。予定の左の線は、一日の予定では塗り、一日の一部の予定では枠になる。一日の予定には「終日」、TimeTreeで時刻つきだった予定にはその時刻が出る。
- 何日も続く予定は、予定の編集画面で「終了日」を入れる。
- 予定の追加画面の「繰り返し」で、毎週（その曜日）・毎月（その日）・毎月の第N営業日を選び、回数を入れると、まとめて作る（作ったあとは1件ずつの予定）。営業日は土日と祝日（振替休日・国民の休日を含む）を除いて数え、日付より前の回と、第N営業日がない月は作らない。作られる日付の最初の3回が画面に出る。
- 繰り返しで作った予定とTimeTreeの繰り返しの予定は、1つのまとまりとして記録する。編集は1件ずつで、削除のときに「この予定だけ」「この日以降」「すべて」を選べる。1.12.0 より前に繰り返しで作った予定は、予定名・種類・メモ・日数が同じで、作った時刻が1秒以内に続いているものを1つのまとまりとみなす。
- 祝日（振替休日・国民の休日を含む）は端末の中で計算する。2019年以降は内閣府の一覧と合わせてある。
- 検索：上の欄に入れると、予定名とメモですべての日付から探す（新しい順）。
- 右上の「種類・取り込み」：予定の種類（名前・色・並び順）、費用の科目と種類の対応、TimeTreeからの取り込み。
- 予定の種類は、科目と同じように、選ぶところの「＋ 追加」からその場で増やせる（予定の追加・編集画面と、入力画面の「＋ 新しい予定」）。名前と色を選んで追加すると、その種類が選ばれた状態に戻る。
- 設定画面の「予定の種類」でも、色・名前の変更と、追加・削除ができる（並べ替えと、費用の科目との対応はカレンダーの「種類・取り込み」から）。

### 予定名と時間

時刻の入力欄はなく、時間は予定名の先頭に書く。読んだ時間は、時間の部分を太字にすること、その日の中の並び順（開始時刻の順）、一日の一部の予定かどうか（下の「一日の予定と一日の一部の予定」）に使う。予定名は書いたまま保存する。

| 予定名 | 時間として読む部分 |
|---|---|
| `19-` / `13-面接` | 19:00 / 13:00 から |
| `10-15` / `1930-22 飲み会` / `10-1530` | 10:00〜15:00 / 19:30〜22:00 / 10:00〜15:30 |
| `930-バイト` / `9〜大学` | 9:30 から / 9:00 から |
| `19:30-`・`19時-`・`19時30分〜` | 19:30 / 19:00 / 19:30 から |
| `19` / `19 飲み` / `1930　飲み` | 19:00 / 19:00 / 19:30 から（予定名が時刻だけか、時刻のあとが空白） |
| `13:00spi` / `14時面接` / `15時半歯医者` | 13:00 / 14:00 / 15:30 から（「:」か「時」で書いた時刻） |
| `面接` / `1-2限 統計` | なし（後ろに「限」が続くものは大学の時限とみなす） |
| `2次試験` / `1組` / `1030サブゼミ` / `1時間勉強` | なし（数字のすぐ後ろに文字が続くもの、「時間」「時限」） |

- 先頭が時刻（1〜2桁は時、3〜4桁は下2桁を分。`19:30`・`19時`・`19時30分`・`19時半` とも書ける）のとき、次のどれかなら時間として読む。時は0〜29。
    - すぐ後ろに「-」「－」「〜」「~」が続く。後ろの時刻を終わりの時刻として読む。
    - 予定名が時刻だけか、時刻のすぐ後ろが空白（半角・全角）。
    - 時刻を「:」か「時」で書いた（後ろに何が続いてもよい。ただし「1時間」「2時限」は読まない）。
- `1030サブゼミ` のように、数字だけの時刻のすぐ後ろに文字が続くものは読まない（`2次試験`・`1組` と区別できないため）。`1030 サブゼミ` か `1030-サブゼミ` と書く。
- iPhoneの日本語のキーボードで「-」を打つと長音の「ー」が入るので、「ー」「ｰ」と、ほかの横棒（「−」「‐」「―」など）も「-」と同じに読む（例：`19ー飲み` → 19:00 から）。
- 予定名の時間を足したり変えたりして保存すると、その日の予定の中で時刻の順の位置に入れ直す。時間を消して保存すると、その日のいちばん下に動く。
- 並べ替え（ドラッグ）はまだない。日付を変えたいときは、予定の編集画面で変える。

### 一日の予定と一日の一部の予定

開始時刻がある予定を「一日の一部の予定」、ない予定を「一日の予定」として、月表示の帯の見た目を分ける。予定の追加・編集画面の予定名の下で、「一日の予定」「一日の一部の予定」を選び直せる。

| 予定 | 開始時刻 | 月表示の帯 |
|---|---|---|
| 一日の一部の予定 | 予定名の先頭の時間（例：`13-面接`）、またはTimeTreeで時刻つきだった予定の時刻 | 種類の色を薄くした背景に、種類の色の文字 |
| 一日の予定 | なし（例：`面接`、`1-2限 統計`、TimeTreeの終日の予定） | 種類の色で塗った背景に、白い文字（明るい色では黒い文字） |

何日も続く予定も、開始時刻があれば一日の一部の予定の見た目になる。

- 予定の追加・編集画面を開いたときは、上の表の決め方で選ばれている。自分で選ばなければ、予定名の先頭の時間を書き足したり消したりしたときに、それに合わせて変わる。
- 自分で選んだものが上の表の決め方と違うときだけ、その選択を予定に記録する（`allDay`）。同じときは記録せず、あとで予定名の時間を変えたときに、それに合わせて変わる。
- 「一日の予定」を選んでも、予定名の先頭の時間は、その日の中の並び順に使う。
- 入力画面の「＋ 新しい予定」で作った予定は、上の表の決め方による。変えるときは、カレンダーで予定を開いて選ぶ。

### 家計簿とつなぐ

入力画面の日付・メモの下に「予定」の1行がある。何も選ばなければ、今までと同じに保存される。

- その日の予定のボタンをタップすると、その記録と予定がつながる（もう一度タップで外れる）。
- 「＋ 新しい予定」で予定名を打つと、保存したときにその日の予定を作ってつなぐ。同じ日に同じ名前の予定があれば、それにつなぐ。
- 新しい予定の種類（色）は、名前の下のボタンで選ぶ。選ばなければ「費用の科目と種類」の対応で自動で選ばれる（収入・振替や対応がないときは「未分類」）。選んだボタンをもう一度タップすると、自動に戻る。
- 履歴で記録を開くと、つながっている予定が1行出る。タップするとカレンダーのその日が開く。
- 予定の編集画面の下に、つながっている支出の記録と合計（立替を除いた自分の分）が出る。
- カレンダーに出る家計簿の記録は支出（費用の科目の行がある記録）だけ。収入・振替の記録は、日の詳細にも予定の編集画面にも出ず、予定の行の金額にも数えない。全額が立替の支出も費用の行がないので出ない。
- 記録を削除しても予定は残る。予定を削除しても記録は残り、つながりだけ外れる。
- 自動入力（固定費）・開始残高・評価額の仕訳はつながない。

### TimeTreeの過去の予定の取り込み

非公式のツール [timetree-exporter](https://pypi.org/project/timetree-exporter/) で `.ics` ファイルに書き出してから読み込む。ツールはTimeTreeのWeb版から読み取る仕組みなので、TimeTree側が変わると動かなくなることがある。

1. パソコンにPython 3.11以上を入れ（timetree-exporter 1.0.0 から3.11以上が必要）、`pip install timetree-exporter` を実行する（Macは `brew install eoleedi/tap/timetree-exporter` でも入る）。
2. `timetree-exporter -o timetree.ics` を実行し、TimeTreeのメールアドレスとパスワードを入れて、書き出すカレンダーを選ぶ。カレンダーが複数あれば、それぞれ書き出す。
3. `.ics` をiCloud DriveかGoogleドライブに置き、アプリの「カレンダー」→「種類・取り込み」→「.ics ファイルを選ぶ」で選ぶ。
4. 件数と期間、ラベル→種類の対応を確かめてから「取り込む」。ラベルで決まらない予定は「名前に○○を含む予定→種類」の決まりで決まり、どれにも当たらなければ「未分類」。

| .ics の項目 | 取り込み先 |
|---|---|
| SUMMARY | 予定名（そのまま） |
| DTSTART / DTEND（終日） | 開始日・終了日（DTEND は翌日を指すので1日引く） |
| DTSTART / DTEND（時刻つき） | 日付と時刻。UTC（末尾が Z）は日本時間に直し、TZID のついた時刻はその時間帯のまま使う（海外で入れた予定は現地の日付になる）。時刻は予定名に付けず、予定に別に保存して、並び順・一日の一部の予定の見た目・編集画面と週表示の時刻の表示に使う |
| DESCRIPTION・LOCATION | メモ（場所は最後に「場所：」を付けて足す） |
| RRULE・RDATE | 1回ずつの予定に分け（取り込む日の1年後まで）、1つのまとまりとして記録する（削除で「この日以降」「すべて」を選べる）。EXDATE の日は作らない |
| UID | 取り込み元として保存し、同じファイルを2回読んでも重複させない |
| CATEGORIES（ラベル名）・COLOR | ラベル→種類の対応に使う |

取り込みをやり直すときは、「種類・取り込み」の「取り込んだファイル」で「まとめて削除」を押す。
