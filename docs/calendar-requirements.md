# 家計簿カレンダー 要件定義（草案）

2026-11-19

## 目的と前提

今の家計簿PWAに「カレンダー」タブを加え、予定と支出を同じアプリで記録する。主な使い方は過去の思い出の振り返り。急に決まって予定に入れていなかった出来事も、家計簿の記録から予定として残す。

**守ること**

- 家計簿の今の機能は変えない。`ledger.js` は変更せず、`tests/ledger.test.mjs` がそのまま通る。
- 今の画面のうち変えるのは3か所だけ：タブが1つ増える、入力画面に「予定」の1行が増える、仕訳の詳細に1行増える。
- オフラインで動く。データはiPhoneの中（IndexedDB）にだけ保存し、サーバーは使わない。
- 家計簿のメモとカレンダーは独立させる。カレンダーに送るのは「予定」欄で選んだり入れたりしたものだけ。

**やらないこと**

- 通知（リマインダー）
- ほかの人との共有、ほかの端末との同期
- 時刻の入力欄と、時間の目盛りのある表示

## 予定名と時間の書き方

時刻の入力欄は作らず、時間は予定名の先頭に書く。数字のない予定名もそのまま使える。その場合は時間なしの予定になるだけ。

| 予定名 | 時間として読む部分 | 開始時刻 |
| --- | --- | --- |
| 19- | 19- | 19:00 |
| 10-15 | 10-15 | 10:00 |
| 13-面接 | 13- | 13:00 |
| 1930-22 飲み会 | 1930-22 | 19:30 |
| 930-バイト | 930- | 9:30 |
| 10-1530 | 10-1530 | 10:00 |
| 9〜大学 | 9〜 | 9:00 |
| 面接 | なし | なし |
| 1-2限 統計 | なし | なし |

- 時間として読むのは、予定名の先頭が時刻で、すぐ後ろに「-」「－」「〜」「~」が続くときだけ。終わりの時刻は書かなくてもよい。
- 時刻の書き方は次のどれか。始まりにも終わりにも使える。
    - 1〜2桁の数字：時（0〜29）。例：`19`
    - 3〜4桁の数字：下2桁を分とする。例：`930` → 9:30、`1930` → 19:30。分が60以上なら時間として読まない
    - `19:30`、`19時`、`19時30分`
- 終わりの数字のすぐ後ろに「限」が続くときは、大学の時限とみなして時間として読まない。
- 読んだ時間の使い道は2つだけ。1つは、表示で時間の部分を太字にすること。もう1つは、新しく入れた予定を、その日の中でどこに置くか決めること。
- 予定名は書いたまま保存し、アプリが書き換えることはない。読み違えても、変わるのは太字の部分と最初の位置だけ。

## 1日の中の並び順とドラッグ

予定の表示順は、時刻とは別に記録する「並び順」で決める。並べ替えても予定名の時間は変わらないので、時間をずらして順番を直す手間がなくなる。

- 新しく入れた予定：開始時刻があれば、その日の予定のうち開始時刻が自分より遅い最初の予定の前に入る。なければ、いちばん下に入る。
- あとで予定名を変えて時刻が変わっても、並び順は自動では動かさない。
- 何日も続く予定は、各日のいちばん上に開始日の早い順でまとめて出す。並べ替えはできない。
- ドラッグ：予定を長押し（約0.4秒）すると持ち上がり、指を離した位置に入る。日の詳細と週表示で使える。長押しになる前に指が動いたときは、画面のスクロールにする。
- 週表示で別の日に動かすと、予定の日付が変わる。その予定に家計簿の記録がつながっていても、記録の日付は変えない。
- 月表示ではドラッグしない（マスが小さいため）。予定の編集画面でも日付を変えられる。
- iPhoneのSafariでは標準のドラッグ＆ドロップ（HTML5）が使いにくいので、Pointer Events で作る。

## 画面

下のタブは「入力・履歴・カレンダー・グラフ・設定」の5つになる。カレンダー画面は、上の切り替えで「月」と「週」を選ぶ。

**月表示**

- 6週分のマスに、予定名を種類の色の帯で出す。入りきらない分は「+2」のように数で出す。
- 何日も続く予定は、日をまたいで横に続く帯にする。
- 今日のマスを目立たせ、土日と祝日の日付に色を付ける。祝日はオフラインで計算する。
- ‹ › と左右のスワイプで月を移動し、「今日」で今月に戻る。
- マスをタップすると、その日の詳細が開く。

**週表示**

- 7日分を縦に並べた一覧にし、時間の目盛りは付けない。
- 各日の予定を並び順で出す。ドラッグで並べ替えと、別の日への移動ができる。

**日の詳細**（下から出るシート。今の家計簿と同じ形）

- その日の予定（ドラッグで並べ替え）と「＋ 予定を追加」。
- その日の家計簿の記録と支出の合計。タップすると今の仕訳の詳細が開く。

**予定の追加・編集**

- 予定名（1行）、種類（色のボタン）、日付、終了日（任意。何日も続く予定）、メモ（任意）。
- 編集画面の下に、つながっている家計簿の記録と、その合計を出す。
- 削除。つながっている記録は消さず、つながりだけ外す。

**検索**

- 予定名とメモで、すべての日付から探す（例：「山」で過去の山行きを一覧にする）。結果は新しい順。

**予定の種類の管理**

- カレンダー画面の右上のボタンから開く。設定画面は変えない。
- 種類ごとに名前と色を決める。色は今の16色と灰色から選ぶ。追加・名前の変更・並べ替え・削除ができ、削除した種類の予定は「未分類」になる。
- 費用の科目と種類の対応を決める（例：遊び→遊び、山→山）。家計簿から作った予定の色に使う。
- 「TimeTreeから取り込む」も同じボタンの中に置く。

## 家計簿との連携

入力画面の日付・メモの下に「予定」の1行を加える。何も選ばなければ、今までとまったく同じに保存される。

- その日の予定が色付きのボタンで並び、最後に「＋ 新しい予定」がある。何日も続く予定は、期間中のどの日にも並ぶ。
- 予定のボタンをタップすると、その記録と予定がつながる。もう一度タップすると外れる。1つの記録につながる予定は1つ。
- 「＋ 新しい予定」で予定名を打つと、保存したときにカレンダーに予定を作ってつなぐ。同じ日に同じ名前の予定があれば、新しく作らずにそれにつなぐ。
- 新しい予定の種類は、費用の科目との対応で決める。収入・振替のときや対応がないときは「未分類」。
- 日付を変えると、並ぶ予定もその日のものに変わる。
- 支出・収入・振替・仕訳のどの画面でも使える。自動入力（固定費）で作られた仕訳はつながない。
- 仕訳を編集するときは、今つながっている予定が選ばれた状態で開く。
- 履歴で記録を開いたとき（仕訳の詳細）、つながっている予定の名前を1行出す。タップするとカレンダーのその日が開く。
- 履歴の一覧・検索、グラフ、設定画面は変えない。

**予定に出す金額**

- 支出は、費用の行の合計（立替を除いた自分の分）。月別の支出と同じ数え方。
- 収入は、収益の行の合計として別に出す。
- 振替だけの記録は金額を数えず、一覧にだけ出す。

**消したとき**

- 記録を削除しても予定は残す。予定を削除しても記録は残し、つながりだけ外す。

## TimeTreeの過去の予定の取り込み

非公式のツール [timetree-exporter](https://pypi.org/project/timetree-exporter/) でTimeTreeの予定を `.ics` ファイルに書き出し、カレンダー画面の「TimeTreeから取り込む」で読み込む。ツールはメールアドレスとパスワードでログインし、TimeTreeのWeb版から読み取る仕組み。TimeTree側が変わると動かなくなることがある。

**手順**

1. パソコンにPython 3.11以上を入れ（1.0.0 から3.11以上が必要）、`pip install timetree-exporter` を実行する（Macは Homebrew の `brew install eoleedi/tap/timetree-exporter` でも入る）。最新版は1.0.0（2026年10月）なので、使う前にPyPIのページで手順を確かめる。
2. `timetree-exporter -o timetree.ics` を実行し、TimeTreeのメールアドレスとパスワードを入れて、書き出すカレンダーを選ぶ。カレンダーが複数あれば、それぞれ書き出す。
3. できた `.ics` をテキストエディタで開き、ラベル（色）・終日・何日も続く予定・繰り返しがどう書かれているかを確かめる。変換ルールを実際のデータに合わせるため。
4. `.ics` をiCloud DriveかGoogleドライブに置き、iPhoneのアプリで「TimeTreeから取り込む」からファイルを選ぶ。
5. 件数と期間を確かめてから取り込む。

**変換ルール**

| .ics の項目 | 取り込み先 |
| --- | --- |
| SUMMARY（名前） | 予定名。そのまま |
| DTSTART / DTEND（終日） | 開始日・終了日。終日の DTEND は翌日を指すので1日引く |
| DTSTART / DTEND（時刻つき） | 日本時間の日付だけ使う。時刻は予定名に付けず、その日の最初の並び順にだけ使う |
| DESCRIPTION（メモ）・LOCATION（場所） | メモ。場所はメモの最後に「場所：」を付けて足す |
| RRULE（繰り返し） | 1回ずつの予定に分ける。取り込む日の1年後まで。EXDATE（除外された日）は作らない |
| UID | 取り込み元として保存し、同じファイルを2回読んでも重複させない |
| ラベル（色） | 書き出されていれば、名前で種類に対応させる |

- 色が書き出されていないときのため、取り込み画面で「名前に○○を含む予定→種類」の決まりを入れられるようにする（例：「バイト」→バイト、「限」→大学）。どれにも当たらない予定は「未分類」。
- 取り込みをやり直せるように、取り込んだ予定をファイルごとにまとめて削除できるようにする。

## データとバックアップ

予定は家計簿のデータ（`state`）の中の `state.calendar` に保存する。今のバックアップの書き出し・復元にそのまま含まれる。

| 置き場所 | 中身 |
| --- | --- |
| `state.calendar.events` | 予定。id、予定名、開始日、終了日（任意）、種類のid、その日の中の並び順、メモ、作成元（手入力・家計簿・TimeTree）、取り込み元のUID（任意）、繰り返しのまとまりのid `series`（任意）、TimeTreeの時刻 `time: { start, end }`（任意。0時からの分）、一日の予定か `allDay`（任意。画面で選んだものが開始時刻から決まるものと違うときだけ） |
| `state.calendar.cats` | 予定の種類。id、名前、色（`s1`〜`s16`・`s-other`）、並び順 |
| `state.calendar.accCat` | 費用の科目のid → 種類のid |
| 仕訳の `eventId` | つながっている予定のid（任意） |

- `ledger.js` の `SCHEMA` と `migrate()` は変えない。`state.calendar` がなければ空で作る処理を `calendar.js` に置き、起動時と復元時に `L.migrate()` のあとで呼ぶ。
- カレンダーを付ける前のバックアップ（`calendar` がない）を復元したときは、今の予定を残す。復元の確認の文にそのことを書く。
- 「すべてのデータを削除」とロックの「忘れた場合」では予定も消える。確認の文に「予定」を加える。
- 仕訳の `eventId` がない予定を指していたら、読み込むときにつながりを外す（エラーにはしない）。
- `?demo` では仮の予定も出す。

## 実装メモ

**ファイル**

- 新しい `calendar.js`：画面に依存しない部分。予定名の時間の読み取り、並び順、`.ics` の読み取りと繰り返しの展開、祝日の計算、`state.calendar` の用意。`ledger.js` と同じく Node.js でテストできる形にする。
- 新しい `tests/calendar.test.mjs`：時間の読み取り（上の表の例すべて）、新しい予定の位置、何日も続く予定、`.ics` の終日・時刻つき・繰り返し・重複、祝日（2026〜2027年を内閣府の一覧と照らし合わせる）。
- `app.js`：カレンダー画面を足す。今の関数で手を入れるのは `newDraft`・`startEdit`・`viewInput`（予定の1行）、`saveEntry`（`eventId`）、`showDetail`（予定名の1行）、`init`・`importBackup`（`state.calendar` の用意）、`VIEWS`、削除の確認の文だけ。
- `index.html`：タブのボタンを1つ足す。
- `style.css`：カレンダー用の指定を足すだけで、今の指定は変えない。
- `sw.js`：`ASSETS` に `./calendar.js` を足し、`CACHE` を `kakeibo-v11` に上げる。
- `APP_VERSION` を `1.8.0` にする。`README.md` にカレンダーの節を足す。

**作る順番**

1. `calendar.js` とテスト（時間の読み取り・並び順・祝日）
2. カレンダー画面（月・週・日の詳細・予定の追加と編集）
3. ドラッグ
4. 家計簿との連携（入力画面の予定の1行、仕訳の詳細）
5. TimeTreeの取り込み（先に実際の `.ics` を見てから）
6. 検索と種類の管理

**確かめること**

- `node --test tests/` がすべて通る。
- `?demo` で、入力・履歴・グラフ・設定の4つの画面が今と同じに動く。
- iPhoneのホーム画面から開き、機内モードで予定の追加・削除・ドラッグができる。
- カレンダーを付ける前のバックアップを復元しても、家計簿の記録が今と同じに戻る。

## 決めること

仮の答えで書いてある点。変えたいものがあれば直す。

| 項目 | 仮の答え |
| --- | --- |
| 週の始まり | 日曜 |
| 予定の種類の最初のセット | バイト・大学・遊び・山・未分類 |
| 月表示のマスに、その日の支出の合計を出すか | 出さない（日の詳細で見る） |
| 新しく入れる予定の繰り返し | 毎週・毎月の日付に、指定した回数ぶんまとめて作る（作ったあとは1件ずつの予定） |
| カレンダーのタブの位置 | 3番目（履歴とグラフの間） |

## 実装後に決まったこと・変わったこと

上の草案から、作りながら決めたこと。今の動きは `README.md` の「カレンダー」の節を正とする。

| 項目 | 決まったこと |
| --- | --- |
| ドラッグ | いったん作らない。予定の並び順は、追加したときに予定名の時刻で決まるだけ（あとから並べ替えはできない）。日付は予定の編集画面で変える |
| 時間として読まない書き方 | 後ろに「限」が続くものだけ。「3-4人」のような書き方は3:00と読んでよい |
| 「変えるのは3か所だけ」 | 守らなくてよい |
| 祝日 | 2019年以降を内閣府の一覧と合わせる（TimeTreeは2019年ごろからしか使っていない） |
| 月表示 | 左右のスワイプでなく、月を縦に並べて続けてスクロールする（端に近づいたら前後の月を足す） |
| 家計簿から作る予定の種類 | 入力画面の「＋ 新しい予定」で選べる。選ばなければ費用の科目との対応で自動 |
| 予定の種類の追加 | 科目と同じように、選ぶところの「＋ 追加」からその場で追加できる（名前と色） |
| 設定画面 | 「予定の種類」を加え、色・名前の変更と、追加・削除ができる（並べ替えと科目との対応はカレンダーの「種類・取り込み」） |
| 繰り返し | 毎週（その曜日）・毎月（その日）・毎月の第N営業日（土日・祝日を除く）。指定した回数ぶん、1件ずつの予定として作る |
| テストの実行 | `node --test tests/` は Node 22 では動かないので `node --test tests/*.test.mjs` |
| 一日の予定と一日の一部の予定（1.12.0） | 開始時刻（予定名の先頭の時間、またはTimeTreeの時刻）があれば一日の一部の予定。月表示では、一日の予定は種類の色で塗って白い文字、一日の一部の予定は種類の色を薄くした背景に種類の色の文字。週表示・日の詳細では左の線を塗りと枠で分け、一日の予定に「終日」を出す |
| TimeTreeの時刻（1.12.0） | 予定名には付けないまま、予定の `time` に保存する（並び順・見た目・時刻の表示に使う）。TZID のついた時刻は、その時間帯の日付のまま使う（海外で入れた予定は現地の日付） |
| 一日の予定か一日の一部の予定かを選ぶ（1.13.0） | 予定の追加・編集画面の予定名の下で選ぶ。開始時刻から決まるものと違うときだけ `allDay` に記録する。自分で選んでいなければ、予定名の時間を書き換えたときに合わせて変わる。入力画面の「＋ 新しい予定」には欄を足さない |
| 繰り返しの予定の削除（1.12.0） | 繰り返しで作った予定とTimeTreeの繰り返しの予定に、まとまりのid `series` を付ける。削除のときに「この予定だけ」「この日以降」「すべて」を選ぶ。編集は1件ずつ。前の版で作った予定は、予定名・種類・メモ・日数が同じで、作った時刻が1秒以内に続くものをまとめる |
